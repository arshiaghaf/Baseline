# Continuous Integration

This repository uses GitHub Actions for pull request and `main` branch validation.

Baseline targets Apple Silicon Macs running macOS 15 or later. CI runs across
the arm64 runners `xcode-27`, `macos-26`, and `macos-15`. Intel CI jobs and
Intel application packages are no longer supported.

The CI workflow:

- Uses Node.js 24.22.2, matching `.node-version`, and installs dependencies with `npm ci`.
- Prepares the checksum-pinned upstream Sparkle framework without accessing keys.
- Lints release scripts with `bash -n`.
- Typechecks the Electron main/preload/renderer TypeScript.
- Runs Vitest unit tests.
- Packages the unsigned Electron app.
- Exercises authenticated fixture updates and rejected feeds, archives, keys and
  failed saves with disposable keys and temporary apps; production keys stay local.
- Runs Playwright Electron smoke tests with initial refresh disabled, temporary
  user data, and an injected test secret provider that never accesses Keychain.
- Runs a production dependency audit.

The smoke tests launch a disposable copy of the packaged app. Test setup rebuilds
only its main-process bundle with a test provider, preserving the production
HMAC verification and tamper handling. Before launch, setup verifies that the
production Keychain provider was excluded. The original package in `out/` keeps
the production provider and is never launched by these tests. Runtime environment
variables cannot select the test provider in a production build.

Installed-app and real Keychain validation still require a separate manual check.

The local equivalent for build and test validation is:

```bash
npm ci
npm run prepare:sparkle
npm run typecheck
npm test
npm run build
BASELINE_SELF_UPDATE_FIXTURE_TESTS=1 npm test -- ElectronTests/selfUpdateLifecycle.test.ts
npm run test:electron
```

Unsigned DMG release artifact builds are handled by `.github/workflows/release.yml` when a `vX.Y.Z` tag is pushed.

Release notes generated by the release helper include the Apple Silicon requirement.
Previously shipped clients cannot receive new compatibility guards: older Intel
builds may still link to the latest release page, so keep that requirement visible
in published notes. Do not replace or delete historical release assets, and do not
claim a last compatible Intel release without inspecting its binaries.

Before publishing an Apple Silicon-only release, update the separate Homebrew tap
cask with `depends_on arch: :arm64` so Intel users cannot install or upgrade to an
incompatible download. Preserve existing installation data; do not add uninstall
or zap actions to perform this transition.
